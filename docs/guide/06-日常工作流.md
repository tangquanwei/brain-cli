# 💡 日常工作流

有了本地化的 TypeScript 核心架构之后，笔记内容通过本地 Markdown 更新。当前 `notes/` 是独立 Git 子模块；`brain backup` 只提交并可推送 notes 仓库。

## 场景 1：突然有灵感 (Capture)

在使用电脑或 VSCode 的时候，突然有一个绝妙想法：

1. `Ctrl + Shift + P` -> 运行任务 `Tasks: Run Task`
2. 选择 **💡 快速捕获想法（本地）**
3. 在弹出的 VS Code 对话框中快捷填入：
   - 标题: `新方案: 利用 LLM 分析日志`
   - 正文: `- 配置 RAG ...`
4. 记录即生成进本地目录对应的 markdown 文件中。

如果你喜欢纯命令行：
```bash
brain capture "新方案: 利用 LLM" -c "配置 RAG" -t "Idea,AI"
```

## 场景 2：重度阅读与沉浸式写作 (Editing)

打开 VS Code 当前项目直接进入 `notes` 文件夹。

- 沉浸于原生的 Markdown 书写
- 随意放入相关资源和截图（使用相应的 Paste image 命令或者相对路径存放）
- 你可以依赖任何偏好的格式化工具

**同时**：注意 Git 边界：
- `notes/` 内的笔记正文属于独立仓库 `https://github.com/<your-account>/notes.git`
- Brain 总控仓库只记录 `notes` 和 `blog` 当前指向的 commit
- `brain backup` / Watcher 不会自动提交总控仓库指针

博客内容属于独立的 `blog/` 子模块。博客本地预览、构建和发布准备都在该目录执行：

```bash
npm --prefix blog run server
npm --prefix blog run build
```

## 场景 3：下班闭环与离线 (Wrap-up)

下班或合上电脑前，查看第二大脑状态：

```bash
brain status
```

如果还有没推的更新或者你想写一个总结性的 commit message：

```bash
brain backup -m "完成关于大模型日志的构思文草稿" --push
```
