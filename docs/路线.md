# 路线图

`brain-cli` 的发展分三个阶段：**管好本地文件 → 提供索引和检索 API → 让 AI Agent 用上检索**。
每个阶段标注当前状态（✅ 已完成 / 🚧 部分完成 / 📋 未开始）和下一步任务。

---

## 阶段一：管理本地文件 ✅ 已完成

> 目标：本地 Markdown + PARA + Git，一条命令管好知识库。

已实现：

- 🏗️ `brain init` 初始化 PARA 目录结构（projects / areas / resources / archives / questions）
- 💡 `brain capture` 快速捕获，frontmatter、目录归属全自动
- ✏️ `brain rename` / `brain move` 安全重构，自动重写引用链接、同步图片目录
- 🔗 `brain links` / `brain backlinks` 链接体检：断链、缺失标题、非标准 WikiLink、孤岛笔记
- 📚 `brain review` 笔记回顾（周 / 月 / 标签 / 随机漫步）
- 💾 `brain backup` + `brain watch` 守护进程：自动提交、定时推送，严格只动 notes 仓库
- 🌐 `brain web` 统一 WebUI：仪表盘 / 笔记 / 回顾 / 链接健康 / 知识图谱，chokidar + SSE 实时刷新

后续只做维护和打磨，不再扩范围。

---

## 阶段二：索引和检索 API 🚧 部分完成

> 目标：笔记内容可以被程序化地索引和检索，为 Agent 接入铺路。

已完成：

- `src/utils/noteIndex.ts` 笔记索引（frontmatter、标签、链接图）
- WebUI HTTP 接口（`src/web/server.ts`，仅监听 `127.0.0.1`）：
  `/api/notes`（支持 `q` / `area` / `tag` 过滤）、`/api/note`、`/api/backlinks`、`/api/graph`、`/api/links`
- WebUI 内标题 / 全文关键词搜索

待办（按优先级）：

1. **CLI 检索命令**：新增 `brain search <关键词>`，支持 `--tag` / `--area` / `--json`，让人和脚本都能在终端直接查。
2. **结构化输出**：主要命令统一支持 `--json`（目前仅 `brain links --json`），保证稳定 exit code，方便程序消费。
3. **检索 API 文档化**：把现有 HTTP 端点的请求 / 响应格式写成文档，明确这是本地只读检索 API。
4. **索引缓存**：笔记量上来后，把索引结果落盘缓存（如 `notes/.brain/index.json`），避免每次全量扫描。
5. **语义检索（可选）**：本地 embedding + 向量索引，支持"按意思找笔记"；不引入云端服务，保持本地优先。

---

## 阶段三：AI Agent 检索使用 📋 未开始

> 目标：AI Agent 能安全地检索和引用笔记，把第二大脑变成 Agent 的长期记忆。

前置依赖：阶段二的 `search --json` 与结构化输出。

待办（按优先级）：

1. **MCP Server**：新增 `brain mcp`，以 MCP 协议暴露工具：
   - 只读优先：`search_notes` / `read_note` / `list_notes` / `backlinks`
   - 写入谨慎开放：`capture_note`（复用 capture 的目录归属与 frontmatter 逻辑）
2. **Agent 友好契约**：检索结果带稳定的笔记 ID / 路径 / 摘要 / 相关度，响应体版本化。
3. **集成示例**：给出 Claude Code / Kimi CLI 等常见 Agent 的接入配置示例（MCP 配置 + 用法片段）。
4. **安全边界**：Agent 读写仍限定在 `NOTES_DIR` 内，路径校验复用现有 `src/utils/paths.ts`；写操作默认需确认或仅开放 capture。

---

## 边界（明确不做）

- 不做云同步 / 多人协作 —— 同步交给 Git，由用户自己掌控。
- 不做笔记编辑器 —— 编辑交给 Obsidian / VS Code，WebUI 只读浏览为主。
- 不引入云端 AI 服务依赖 —— 语义检索如实现，只用本地方案。
